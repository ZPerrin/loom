# 0.2.0 implementation plan

Order of operations for the living-specs release defined in the
[roadmap](../../docs/roadmap.md). One numbered item is one work session; each ends when its
exit line is true. Sessions open with warp and close with weave; friction goes to the RSI retro,
not to this file. This plan is the first document under the `.loom/plans/` convention it helps
ship — dated, `kind: plan`, committed here by choice.

## Order

1. **Spec checks in doc-linter.** ~~Port `speclint.py` behind a rail~~ — reversed 2026-09-05:
   the checker is awk (`scripts/lib/lint-spec.awk`) so the parser can be shared with the slicer
   in 7; the python original proved parity at the port and was retired (fixtures hold the
   recorded expectations). Budgets and word lists
   from `[lint.specs]` with shipped defaults; findings keyed by rule + requirement id; conforming
   and violating fixtures under `tests/fixtures/`, run by `tests/run`.
   Exit: `bash tests/run` green including spec fixtures; `doc-linter` output unchanged for a repo
   with no specs. **Done 2026-09-05** (delegates α checker, β fixtures; coordinator integration).
2. **Control surfaces.** The reference project and doc convention learn the data plane:
   `.loom/specs/`, `.loom/plans/`, dated naming, commit-or-ignore as the owner's call, the
   `[lint.specs]` keys, the location override keys. dress inherits all of it through Propose.
   Exit: dress on a fixture repo proposes the data plane with no new skill prose.
   **Done 2026-09-05**, exit half met: the data plane lives in the reference project and doc
   convention, `[specs]`/`[plans]` keys lint under LAYOUT; dress proposed it on Haiku, not on
   Sonnet. The missing Propose bullet is skill prose and goes to 6.
3. **Grammar and writing rules.** `references/spec-grammar.md` and
   `references/spec-writing-rules.md`, re-ratified: two modalities, single document, change-log
   section, status lifecycle, permanent ids, wrong/right/why form. Fold the research survey.
   Adjust the linter and fixtures wherever the re-ratified grammar diverges from the bundle.
   Exit: fixtures conform to the written grammar; both references sized for whole injection.
4. **Spec authoring skill.** Fresh, house format: contract paragraph, control-surfaces table, few
   hard constraints, output contract; references load by the most deterministic mechanism the
   harness allows, prose read-trigger as the floor.
   Exit: authors loom's own first repo spec, lint-clean.
5. **Spec reconciliation skill.** Fresh, refine-docs lineage. Evidence order tests > code >
   sampled runtime; brownfield is reconciliation against an empty spec; findings land as
   change-log lines plus proposed edits, never silent rewrites.
   Exit: reconciles the spec from 4 against the codebase and reports drift by id.
6. **Dogfood loop.** Both skills on loom itself and on one external repo; retro friction into
   overrides; run the skill-format ablations from the roadmap Ideas now that speclint grades.
   Exit: retro filed; ablation results recorded for 8.
7. **Spec-aware slicing.** `doc-slicer` or a sibling addresses specs by capability, id, section,
   reusing the parser in `lib/lint-spec.awk`.
   Opt-in like all slicing.
   Exit: one recipe yields identical bytes across runs.
8. **Skill-authoring meta-reference.** House format, constraints-over-steps as the maintenance
   rule, distilled external technique, grounded in 6.
   Exit: the existing four skills pass the standard or file their gap.
9. **Orchestrator review.** Piece by piece per the roadmap; decide the retire-to-workspace
   pattern.
10. **Release.** weft cohesion pass; smoke-test the install on Claude Code and Codex; promote
    and tag only with explicit approval.
