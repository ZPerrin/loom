# 0.2.0 implementation plan

Order of operations for the living-specs release defined in the
[roadmap](../../docs/roadmap.md). One numbered item is one work session; each ends when its
exit line is true. Sessions open with warp and close with weave; friction goes to the RSI retro,
not to this file. This plan is the first document under the `.loom/plans/` convention it helps
ship — dated, `kind: plan`, committed here by choice.

## Order

1. **Spec checks in doc-linter.** An awk checker, `scripts/lib/lint-spec.awk`, its parser shared
   with the slicer in 7. Budgets and word lists from `[lint.specs]` with shipped defaults;
   findings keyed by rule + requirement id; conforming and violating fixtures under
   `tests/fixtures/`, run by `tests/run`.
   Exit: `bash tests/run` green including spec fixtures; `doc-linter` output unchanged for a repo
   with no specs. **Done 2026-09-05.**
2. **Control surfaces.** The reference project and doc convention learn the data plane:
   `.loom/specs/`, `.loom/plans/`, dated naming, commit-or-ignore as the operator's call, the
   `[lint.specs]` keys, the location override keys. dress inherits all of it through Propose.
   Exit: dress on a fixture repo proposes the data plane with no new skill prose.
   **Done 2026-09-05**, exit half met: dress proposed the data plane on Haiku, not on Sonnet.
3. **Grammar and writing rules.** `references/spec-grammar.md` and
   `references/spec-writing-rules.md`, re-ratified: two modalities, single document, change-log
   section, status lifecycle, permanent ids, wrong/right/why form. Fold the research survey.
   Adjust the linter and fixtures wherever the re-ratified grammar diverges from the bundle.
   Exit: fixtures conform to the written grammar; both references sized for whole injection.
   **Done 2026-09-05.**
4. **Spec authoring skill.** Fresh, house format: contract paragraph, control-surfaces table, few
   hard constraints, output contract; references load by the most deterministic mechanism the
   harness allows, prose read-trigger as the floor.
   Exit: authors loom's own first repo spec, lint-clean. **Done 2026-09-05.**
5. **Spec reconciliation skill.** Fresh, refine-docs lineage. Evidence order tests > code >
   sampled runtime; brownfield is reconciliation against an empty spec; the writing is `spec`'s
   in both entry states; findings land as change-log lines plus proposed edits, never silent
   rewrites.
   Exit: reconciles `docs/specs/managed-docs.md` against the codebase and reports drift by id, on
   Sonnet, one run. **Done 2026-09-05.**
6. **Dogfood loop.** Both skills on loom itself; retro friction into overrides; run the
   skill-format ablations from the roadmap Ideas now that `doc-linter` grades specs.
   Exit: retro filed; ablation results recorded for 8. **Done 2026-09-06** but for the ablations,
   which open 9: four specs at feature grain, all four reconciled against the code, the whole
   markdown set given a cohesion pass, retro filed. The external-repo run was cut 2026-09-06: the
   operator is loom's only user until it nears 1.0, and his own repos exercise 0.2.0 as it ships.
7. **Spec-aware slicing, with the cohesion pass and the first enforced hook.** `doc-slicer --spec
   <capability> [id|section]`: the spec found by its Capability line among the managed `kind: spec`
   docs, one requirement block by id, one section by name, one line by INV or N id, and an id
   index; a small awk of its own over the grammar's header shapes, since the linter's parser is
   entangled with its checks. Opt-in like all slicing. The cohesion pass over the six skills: one
   pointer to the reference project with its path, weave's Reconcile step renamed Scope, the
   retro's second half (an experiment whose test has run is resolved into opinion or deleted),
   owner renamed operator. The first tool-call hook: on a write to a managed doc, run doc-linter
   and return the findings as context, the skill prose that names the linter left as the floor.
   Exit: one slicing recipe yields identical bytes across runs; the hook script returns findings
   for a fixture write on stdin, with the live check at the next session's first turn; `bash
   tests/run` green. **Done 2026-09-07**, and past its exit line: the opinion gate on both
   invocation paths, hooks by name under `.loom/scripts/`, the overrides under `.loom/skills/`,
   the change log holding only open lines with L002 behind it, the tracer, CLAUDE.md importing
   AGENTS.md, and three read-only reconciliations on the result. Codex desktop's refreshed
   install passed native bearings, lint, picker and short-mention checks; its picker matcher
   needed a correction. The [validation report](../reports/2026-09-07-codex-hooks-validation.md)
   records the remaining routing and prose-floor gaps for Claude review.
8. **Orchestration state.** Review the orchestrator repo piece by piece per the roadmap. Port the
   handoff template into the reference project as `kind: handoff`, dated under `.loom/handoffs/`;
   a delegate worktree carries `.loom/handoff` naming its brief, and the session slice opens with
   the brief in place of the configured headers; the worktree-and-marker recipe becomes
   `.loom/scripts/delegate`. Whether the s7 handoffs move in is the operator's call. Decide the
   retire-to-workspace pattern.
   Review warp's Open step and the [warp] keys against the harness-made worktree: the harness opens
   the workspace before warp runs, so the keys the section requires are ceremony; make each
   optional with a default, and leave renaming the branch to a repo's hook.
   Exit: a delegate session in a marked worktree opens with its handoff and no roadmap slice.
9. **Skill-authoring meta-reference.** House format, constraints-over-steps as the maintenance
   rule, distilled external technique, grounded in 6; the ablations run first.
   Exit: the six skills pass the standard or file their gap.
10. **Release.** weft cohesion pass; smoke-test the install on Claude Code and Codex. On Codex:
    hooks are on by default and each plugin hook is trusted at its prompt; register hook-trace on
    every event for one session, invoke a skill by $mention and by conversation, read the trace,
    and point the gate at what fired. On Claude: type
    /loom:spec once to see References render and the gate fire on the typed path, and invoke a
    skill by conversation to see it fire on the Skill tool. Promote and tag only with explicit
    approval. The Claude routes were checked live on 2026-09-07 and the gate's receipt and the
    skills' shared floor landed; hooks take no input; lint on write is unregistered and the skills run
    the linter at their steps; the read adapter is a non-goal; the temporary project probes are
    retired.
